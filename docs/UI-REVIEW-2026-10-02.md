## 总评

- 1920 空桌面构图与参考图高度接近，是目前最大优点。
- 可用性（Nielsen 十项）**16/40**，偏低。主要扣分：用户控制（弹层关不掉）、识别（左栏无标签且提示失效）、错误恢复、帮助。
- 设计辨识度：品牌感几乎全靠一张壁纸与 logo；「Calm Future / 日式未来感」未在字体、动效、文案中落地；外壳（固定白字）与应用窗口（随主题墨字）像两套系统。

## P0 · 第一批修复

### [x] 1. 外壳白字对比度不足（全外壳 WCAG 1.4.3 / 1.4.11 不达标）

- **问题**：浅色玻璃 + 亮蓝天空上的白字普遍看不清；与应用窗口重叠时几乎消失（1366 下启动器盖在 Files 上接近 1:1）。
- **实测对比度**（按真实背景像素合成）：

  | 元素 | 对比度 |
  |---|---|
  | 菜单栏标签（13px） | 2.1:1 |
  | 菜单栏时钟 / 日期（12px） | 1.7–1.8:1 |
  | 菜单栏电量「100%」（11px） | 1.8:1 |
  | 菜单栏用户名（12px） | 2.0:1 |
  | 通知中心标题 | 2.0:1 |
  | 通知中心空态「暂无通知」 | 1.8:1 |
  | 启动器分类 | 2.7:1 |
  | 品牌标语 / 副标语 | 3.1:1 / 2.3:1 |
  | 品牌「OS」渐变字 | 约 2.0–2.8:1 |
  | 小组件日期 / 「多云 深圳」 | 3.6:1 / 3.2:1 |
  | 小组件「暂无通知」/ 禁用「清空」 | 2.4:1 / 1.6:1 |
  | 焦点环（`--ag-primary` 65%）对天空 | 1.1–1.4:1 |

- **依据**：`src/index.css` 约 387 行 `.desktop-chrome` 把 text 强制为 `#fff`、muted 为白 78%，叠在 12–26% 白玻璃上。参考图的启动器与小组件用的是不透明白玻璃 + 深色字。
- **方案**：
  - 弹层（启动器、通知中心、菜单下拉、右键菜单、用户菜单、搜索面板）：72–86% 白玻璃 + 墨色字（`--ag-text` / `--ag-text-muted`），从 `.desktop-chrome` 的白字重映射中豁免。
  - 右栏小组件卡：同上，提高底色不透明度，muted 文字改用达标墨色；禁用态不要只靠 40% 透明度。
  - 菜单栏：保留白字，`.menubar-glass` 压暗到约 `rgb(16 28 64 / 40%)`。
  - 品牌层：标语与副标语加强 text-shadow 或提高字重 / 字号，「OS」渐变选更深的色标。
  - 焦点环：双环（外白 2px + 内墨 1px），任意背景可见。
  - `index.css.test` 加对比度门禁：对壁纸最亮区域与 `--ag-surface` 分别合成计算，< 4.5:1（大字 < 3:1）即失败。
- **验收**：上表所有元素 ≥ 4.5:1（大字 ≥ 3:1）；焦点环 ≥ 3:1；1366 下启动器压在 Files 窗口上文字清晰可读。

### [x] 2. 启动器、通知中心无法关闭；弹层不互斥

- **问题**：
  - 启动器点击打开后焦点留在「开始」按钮，Esc 处理挂在 portal 出去的 `<menu>` 上（`src/desktop/taskbar/AppLauncher.tsx:237`），按 Esc 无效；无外部点击关闭；Ctrl+K 会叠在其上。DESIGN.md §31 写的「Esc 挂触发器 + 菜单共同 wrapper」在 portal 改造后已失效（回归）。
  - `src/desktop/taskbar/NotificationCenter.tsx` 完全没有 Esc / 外部点击关闭。
  - 通知中心面板（x 1351–1671）与右栏时钟卡（x 1612–1900）重叠约 59px。
  - 实测启动器、通知中心、Ctrl+K 搜索三者可同时打开。
- **方案**：
  - 抽共享 hook `usePopoverDismiss`：document 级捕获阶段 Esc、外部 pointerdown 关闭、全局唯一「当前弹层」槽（打开一个即关闭其他，含 `search-store`）。
  - 启动器打开时自动聚焦 `launcher-search`。
  - 通知中心锚定到 `--ag-rail-right-width` 左侧（或菜单栏下方不与右栏相交）。
  - 同步修订 DESIGN.md §31 的 Esc 契约描述。
- **验收**：E2E 覆盖每个弹层的 Esc 关闭、外部点击关闭、两两互斥；通知中心与右栏无几何重叠（boundingBox 断言）。

## P1

### [x] 3. 左栏 tooltip 从未显示（CSS 层叠 bug）+ 瓷贴难区分

- **问题**：悬停与键盘聚焦时 tooltip computed opacity 恒为 0，只剩延迟出现的原生 `title`。
- **依据**：`src/index.css:520` 的 `.os-tooltip { opacity: 0 }` 不在任何 `@layer` 中（全文件无 `@layer`）；Tailwind 4 工具类位于 `@layer utilities`，未分层样式优先级更高，`src/desktop/sidebar/Sidebar.tsx:212` 的 `group-hover:opacity-100 group-focus-visible:opacity-100` 永远不生效。jsdom 不做层叠计算，单测抓不到。
- **方案**：
  - `.os-tooltip` 移入 `@layer components`，或显式写 `.group:hover > .os-tooltip, .group:focus-visible > .os-tooltip { opacity: 1 }`。
  - 排查 `index.css` 中其他「未分层基态 + Tailwind 状态类覆盖」的同类写法。
  - `TILE_GRADIENTS` 中 terminal `#3a4356` / settings `#4a5568` / notifications `#2b3757` 换成有区分度的色相。
  - 评估恢复文字标签（参考图为带标签左栏；80px 宽可容 11px 两字标签）。
- **验收**：E2E 悬停 / 聚焦后读 computed opacity === 1；三个瓷贴色相明显不同。

### [x] 4. 假数据与开发者黑话直接展示给用户

- **假数据**：
  - 天气「24°C 多云 深圳」写死在 `src/desktop/widgets/WidgetRail.tsx:83–88`。
  - 「CPU」实为 rAF 帧抖动估算，截图中恒为 95–99%（无头软渲染会放大，但标成 CPU 本身误导）。
  - 菜单栏 Wi-Fi / 蓝牙图标为纯示意。
- **黑话 / 泄漏文案**（`src/core/i18n` 词典）：
  - `settings.motionGlowHint`：「…（2026-10-01 裁决默认开）」
  - `settings.motionGroupHint`：「动效实验室 · 进阶炫技档…」
  - 商店描述：「Type B 沙箱示例应用」「SDK 示例应用：便签经沙箱桥持久化」
  - 动态面板：「决策来源 本地规则」「AI 生成 · 本地规则」
  - `store.remoteInvalid` 在本地模式（无远程目录）下也显示
  - Files 系统文件夹显示英文名（Desktop / Documents / Music / Trash / System…），路径显示裸「/」
- **方案**：
  - 天气行删除或替换为当前壁纸名。
  - 「CPU」改名「流畅度」并显示 fps，或删除该指标。
  - 隐藏 Wi-Fi / 蓝牙示意图标。
  - 重写上述词条为面向用户的中文（中英双词典同步）。
  - 无远程目录时不提示签名校验失败。
  - Files 加系统文件夹显示名映射（底层路径不变），根路径显示「此设备」之类的可读名。
- **验收**：界面中不再出现示例数据、裁决日期、内部术语；文件夹中文显示。

### [~] 5. 深色主题只做了一半；开机字标不可见

- **问题**：
  - 深色主题下壁纸与 `.desktop-chrome` 不变，只有窗口变暗——深色窗口漂浮在白天天空上。
  - 开机屏使用 `agehaos-logo-v2-full-512.png`，深色字标落在固定深色背景（`--ag-boot-*` 不随主题）上，「Ageha」消失只剩「OS」；进度条贴得过近。
- **方案**：
  - 深色主题配黄昏 / 夜景版壁纸（只做缩放 / 裁切，符合资产规则），或回落到已有暗色 gradient-field。
  - 外壳玻璃色调跟随主题。
  - 开机屏改为 mark 图形 + CSS 文字字标（白字，「OS」渐变），与进度条间距 ≥ 16px。
- **验收**：深色主题下外壳、壁纸、窗口观感统一；开机屏完整显示「AgehaOS」。

## P2

### [ ] 6. 入口重复、首屏信息过载

- **问题**：
  - 桌面约 26 个可点目标；同一功能入口数：设置 6 处（左栏 ×2、Dock、启动器、右键菜单、帮助→关于）、Files 4、商店 4、通知 3、搜索 3；回收站 3 种形态（Dock、Files 侧栏「回收站」、Trash 文件夹）。
  - 首次登录自动打开动态面板窗口，与品牌字、小组件、Dock 争夺注意力。
  - 认知负荷清单 8 项中 6 项不通过（单一焦点、分组 ≤4、视觉层级、一次一件事、选项 ≤4、工作记忆）。
- **方案**：
  - 区域分工：左栏 = 系统位置与面板（桌面、通知、云同步、用户）；Dock = 应用；菜单栏 = 命令与状态。删除左栏与 Dock 重复的 Files / 终端 / 商店 / 设置瓷贴。
  - 编辑命令移回「编辑」菜单或移出菜单栏。
  - 首次登录不自动开动态面板，改为右栏卡片入口。
  - 启动器「推荐」三项与网格重复且副标题都是「最近使用」——改为真正的推荐或删除；「设置」分类只有一个应用，合并。
- **验收**：每个功能主入口 ≤ 2 处；首屏无自动弹出窗口。

### [x] 7. 键盘与读屏可达性

- **问题**：
  - Tab 顺序为左栏 → 小组件 → 菜单栏 → Dock（左右栏为解决层级问题提前渲染，§27）。
  - 无 `h1`、无 `main` 地标、无跳转链接；两个未命名 `<header>` 与一个未命名 `<nav>`。
  - 启动器按钮声明 `aria-haspopup="menu"`，弹层却是普通按钮列表（无 `menuitem`、无 roving focus）；通知中心是无焦点管理的 `region`。
  - 交通灯图标只在悬停时显示。
  - Dock 瓷贴可读名称随运行中窗口标题变化。
  - 10px 字号：通知时间戳、「全部已读」、网速「MB/s」、kbd 徽标；徽章 9px。
- **方案**：
  - DOM 顺序与视觉顺序对齐（菜单栏在前），层级用 z-index 解决而非渲染顺序；或加 `tabindex` 分区与跳转链接。
  - 补地标：`main`（窗口层）、命名的 `nav`（左栏、Dock）、视觉隐藏的 `h1`。
  - 启动器改为 `role="menu"` + `menuitem` + 方向键 roving focus，或去掉 `aria-haspopup="menu"` 改为 `dialog` 语义。
  - 交通灯聚焦时也显示图标。
  - Dock 瓷贴名称固定为应用名，运行状态用 `aria-describedby` 补充。
  - 最小字号提到 11px（DESIGN.md §5 已有此规范）。
- **验收**：键盘可完成「打开启动器 → 启动应用 → 关闭窗口」全流程；axe 无 serious 级问题。

### [x] 8. 效率与帮助

- **问题**：无打开启动器 / 关闭窗口快捷键；Alt+W 未在界面披露；菜单项不显示快捷键；启动器占位符写「搜索应用、文件或命令」实际只搜应用名；Windows 上显示「⌘ K」；最大化后 Esc 不能还原；「帮助」菜单只有「关于」。
- **方案**：
  - 增加快捷键（如 Alt+Space 启动器、Alt+F4 / Ctrl+W 关窗），菜单项右侧显示快捷键。
  - 按平台显示 Ctrl / ⌘。
  - 启动器占位符与实际能力一致，或接入文件搜索（复用 Ctrl+K 搜索服务）。
  - 「帮助」菜单加「键盘快捷键」面板与简短新手引导。
- **验收**：所有快捷键在界面可发现；帮助菜单有实际内容。
